  <name>Task 1: Merge attribution into useResourceImages hook</name>
  <files>src/renderer/hooks/useResourceImages.ts</files>
  <action>
Modify `useResourceImages` to also call `window.api.game.getCuratedImages({})` on mount (alongside the existing `scanResourceImages` call) and merge the attribution metadata into the returned data.

Current return shape:
```
ports: Record<string, string>         // portId -> URL
goods: Record<string, string[]>       // goodId -> URL[]
```

New return shape:
```
ports: Record<string, { url: string; attribution: string; sourceUrl: string }>
goods: Record<string, Array<{ url: string; attribution: string; sourceUrl: string }>>
```

Implementation details:
1. After `scanResourceImages()` succeeds, also call `window.api.game.getCuratedImages({})` to get ALL curated image metadata (no filter args = return all).

   WAIT -- the `getCuratedImages` IPC expects `{ goodId?: string; portId?: string }`. Passing `{}` might return nothing or error. Check the handler: it only queries when goodId or portId is provided. So instead, make TWO approaches:
   - For each portId found in the scan results, call `getCuratedImages({ portId })` 
   - For each goodId found in the scan results, call `getCuratedImages({ goodId })`
   
   But that's N+M IPC calls. Better approach: fetch all curated images by iterating the scan results. Actually, the simplest approach is to batch: call once per port and once per good using Promise.all.

   Actually, the SIMPLEST approach given the existing code: For each portId in `response.data.ports`, call `getCuratedImages({ portId })`. For each goodId in `response.data.goods`, call `getCuratedImages({ goodId })`. Use Promise.all to parallelize. This is at most 25 + 8 = 33 lightweight DB queries (no network), so performance is fine.

2. Build the enriched maps by matching file paths from the scan to attribution from the curated_images query. The curated_images table has a `filePath` column that can be matched against the relative path from the scan.

3. Update the `ResourceImages` interface to use the new shape.

4. Keep `ready: boolean` in the return type. Set `ready: true` only after BOTH scan and attribution queries complete.

5. If attribution lookup fails for any image, fall back to `{ url, attribution: '', sourceUrl: '' }` so the component still renders.
  </action>
