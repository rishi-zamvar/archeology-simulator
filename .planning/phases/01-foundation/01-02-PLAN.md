  <behavior>
    Database layer:
    - initializeDatabase() creates game_state and saves_history tables in WAL mode; idempotent (IF NOT EXISTS)
    - saveGameStateAtomic(db, state) writes to game_state and saves_history in a single transaction; if either insert fails, both roll back
    - loadGameState(db) returns parsed GameState or null if no save exists
    - Saving an invalid JSON state throws before writing to DB

    FSM game state:
    - GameState is a discriminated union: { type: 'idle'; currentTurn: number } | { type: 'trading'; currentTurn: number; selectedPort: string } | { type: 'sailing'; currentTurn: number; destination: string; eta: number } | { type: 'encountered'; currentTurn: number; eventType: string }
    - handleAction(current, action) returns new GameState for valid transitions
    - handleAction throws Error('Invalid transition: {from} -> {action.type}') for invalid transitions
    - Valid transitions: idle->START_TRADE->trading, trading->COMPLETE_TRADE->idle, idle->SET_SAIL->sailing, sailing->ARRIVE->idle, sailing->ENCOUNTER->encountered, encountered->RESOLVE->idle

    IPC wiring:
    - game:load handler calls loadGameState; returns null state as initial idle state { type: 'idle', currentTurn: 0 }
    - game:save handler validates state shape, calls saveGameStateAtomic, returns { success: boolean }
    - game:action handler calls handleAction from game engine, auto-saves result, returns GameResult

    Cases (FSM):
    - handleAction({ type: 'idle', currentTurn: 1 }, { type: 'START_TRADE', port: 'Alexandria' }) -> { type: 'trading', currentTurn: 1, selectedPort: 'Alexandria' }
    - handleAction({ type: 'trading', ... }, { type: 'SET_SAIL', ... }) -> throws 'Invalid transition: trading -> SET_SAIL'
    - handleAction({ type: 'idle', currentTurn: 5 }, { type: 'SET_SAIL', destination: 'Rome', eta: 3 }) -> { type: 'sailing', currentTurn: 5, destination: 'Rome', eta: 3 }

    Cases (DB):
    - saveGameStateAtomic then loadGameState returns equivalent state
    - Concurrent saves (two writes back to back) — second write wins, no lock errors
  </behavior>
