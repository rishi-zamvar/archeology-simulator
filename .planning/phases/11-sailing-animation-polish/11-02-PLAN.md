  <action>
    Rewrite ShipMarker.tsx to replace the current single-shot 5s animation with a per-turn segmented animation loop. Keep the existing MotionLayer interface, LeafletWithMotion cast, and createShipIcon function unchanged.

    **1. Add static dashed route line (SAIL-01):**
    - On mount (when sailingState changes), create an `L.polyline` with the full route `[startCoords, endCoords]`
    - Style: `{ color: '#7a5c45', weight: 2, dashArray: '10, 8', opacity: 0.7 }`
    - Add to map, store ref, remove on cleanup
    - This is SEPARATE from the motion polyline — it stays visible the entire voyage

    **2. Calculate distance-proportional duration (SAIL-02):**
    - Import `calculateAnimationDuration` from `../../game/sailing`
    - Get total turns from `sailingState.voyageTurnsTotal ?? 1`
    - Compute `totalMs = calculateAnimationDuration(totalTurns)`
    - Each segment duration = `totalMs / totalTurns`

    **3. Segmented per-turn animation loop (SAIL-05):**
    - Replace the single `lm.motion.polyline(start, end, { duration: 5000 })` with an async loop
    - For each turn `i` from 0 to totalTurns-1:
      a. Compute segment start/end using `interpolateLatLng` with `t0 = i/totalTurns` and `t1 = (i+1)/totalTurns`
      b. Create a new leaflet.motion polyline for just this segment with `duration: msPerTurn`
      c. Wait for 'motion-ended' event on the segment (wrap in a Promise)
      d. Remove the segment motion layer
      e. Call `window.api.game.advanceSailingTurn()` via IPC
      f. If result has an event (result.data.event !== null), the game state transitions to 'encountered' — the EventCard will appear. Wait for the gameState to return to 'sailing' before continuing the loop. Use a polling approach: check gameState.type every 200ms via a ref.
      g. If result.data.arrived is true, fire `window.api.game.action({ type: 'ARRIVE' })` then `window.api.game.action({ type: 'START_TRADE', port: destination })` and break the loop
    - Use a `cleanedUp` ref to abort the loop if the component unmounts

    **4. Camera follow (SAIL-03):**
    - After each segment animation completes, call `map.panTo(segEnd, { animate: true, duration: 0.3 })` to smoothly track the ship
    - Before starting the animation, call `map.fitBounds(L.latLngBounds(startCoords, endCoords).pad(0.2))` to frame the full route

    **5. Callback for overlay updates:**
    - Add a new prop `onTurnAdvanced?: (result: SailingTurnResult) => void` to ShipMarkerProps
    - After each advanceSailingTurn IPC call, invoke this callback so Shell.tsx can pass turn data to SailingOverlay
    - Also add `onVoyageStarted?: (totalTurns: number) => void` called at the start of the animation loop

    **6. Cleanup:**
    - On unmount or when sailingState changes: set cleanedUp flag, stop any in-progress motion layer, remove route line, remove motion layers
    - Guard all async continuations with cleanedUp check

    **Effect dependencies:** Use `[map, destination, departurePortId, portCoords]` as before (voyageId pattern). Do NOT add voyageTurnsTotal/voyageTurnsElapsed as deps — those change during the voyage and would restart the effect.

    **Important anti-patterns to avoid (from RESEARCH.md):**
    - Do NOT try to pause/resume a single long leaflet.motion animation — use per-segment approach
    - Do NOT add portCoords to effect deps without memoization — it will cause animation restarts
    - Guard motion-ended callbacks with cleanedUp check to prevent stale ARRIVE calls
