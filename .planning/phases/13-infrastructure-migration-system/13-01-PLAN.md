**schema.ts refactor:**

1. Add `import { createLogger } from '../lib/logger';` and `const log = createLogger('Migrations');` at top.

2. Define `type Migration = (db: Database.Database) => void;`

3. Create the MIGRATIONS array with 7 entries:
   - v1 (index 0): All 10 existing CREATE TABLE IF NOT EXISTS statements (moved verbatim from current initializeDatabase). Include the indexes for artifact_cache, curated_images, and journal_entries. Use IF NOT EXISTS because this must be idempotent for v1.3 upgrades per Pitfall 1.
   - v2 (index 1): ALTER TABLE ports ADD COLUMN cultural_description TEXT wrapped in try/catch (duplicate column safe per Pitfall 2). This is the ONE migration where catch is acceptable.
   - v3 (index 2): CREATE TABLE quest_progress (quest_id TEXT PRIMARY KEY, status TEXT NOT NULL, current_objective INTEGER NOT NULL DEFAULT 0, started_at TEXT, completed_at TEXT)
   - v4 (index 3): CREATE TABLE npc_dialogue_state (npc_id TEXT PRIMARY KEY, last_node_id TEXT, times_spoken INTEGER NOT NULL DEFAULT 0, last_spoken_turn INTEGER)
   - v5 (index 4): CREATE TABLE reputation (region TEXT PRIMARY KEY, score INTEGER NOT NULL DEFAULT 0)
   - v6 (index 5): CREATE TABLE port_lore (port_id TEXT PRIMARY KEY, history TEXT, culture TEXT, trade_specialization TEXT, notable_facts_json TEXT, historical_period TEXT, primary_sources_json TEXT)
   - v7 (index 6): CREATE TABLE port_access (port_id TEXT PRIMARY KEY, discovered INTEGER NOT NULL DEFAULT 0, discovered_turn INTEGER, unlock_method TEXT)

4. Create `export const PLAYER_DATA_TABLES` as const array: ['game_state', 'saves_history', 'transaction_history', 'journal_entries', 'player_inventory', 'quest_progress', 'npc_dialogue_state', 'reputation', 'port_access']. Note: port_lore is reference data and NOT included. schema_version is NOT included.

5. Create `function runMigrations(db: Database.Database): void` that:
   - Creates schema_version table with IF NOT EXISTS (single column: version INTEGER NOT NULL DEFAULT 0)
   - Adds migrated_at TEXT column to schema_version (for debugging, per CONTEXT.md specifics)
   - Reads current version; if no row exists, inserts version=0
   - Loops from currentVersion to MIGRATIONS.length, wrapping each migration in its own db.transaction() (per Pitfall 5)
   - Inside each transaction: runs the migration function, then updates schema_version SET version = i+1, migrated_at = datetime('now')
   - Logs each migration: `log.info('Migration applied', { from: i, to: i + 1 })`
   - On failure: let the error propagate (abort strategy per RESEARCH.md recommendation). The transaction auto-rolls back.

6. Refactor initializeDatabase(dbPath):
   - Keep: `new Database(dbPath)`, WAL pragma
   - Replace: the big transaction with all CREATE TABLEs -> call `runMigrations(db)` instead
   - Remove: the standalone ALTER TABLE try/catch (now in migration v2)
   - Return db as before
