  <action>
Add a new IPC handler `image:search-good-candidates` to src/main/ipc/game.ts that:

1. Accepts `{ goodId: string }` where goodId is one of: grain, olive_oil, wine
2. Uses these search terms per good (use multiple compound terms to get diverse results — run 2 searches per good and merge):
   - grain:
     - Primary: "ancient grain amphora storage vessel Egyptian"
     - Secondary: "Roman dolium storage jar grain ancient"
   - olive_oil:
     - Primary: "ancient olive oil amphora vessel Greek"
     - Secondary: "ancient oil storage jar oinochoe Mediterranean"
   - wine:
     - Primary: "ancient wine krater vessel Greek amphora"
     - Secondary: "Roman wine storage amphora lagynos ancient"
3. For each search term, call Met Museum search:
   - GET https://collectionapi.metmuseum.org/public/collection/v1/search?q={term}&hasImages=true&isPublicDomain=true
   - Fetch detail for each objectID (skip first 2, sample up to 10 IDs spaced every other one)
   - Gate per detail: obj.isPublicDomain === true AND obj.primaryImage?.trim() non-empty
   - Deduplicate by objectID across both search passes
   - Collect up to 8 valid Met candidates total (before user filtering)
4. If Met returns fewer than 3 candidates total, fallback to Wikimedia Commons using the primary search term for the good:
   - GET https://commons.wikimedia.org/w/api.php?action=query&list=search&srsearch={term}&srnamespace=6&srlimit=10&format=json&origin=*
   - Filter out: "modern", "20th", "diagram", "painting", "portrait" in title
   - Collect up to 3 Wikimedia candidates
5. Return `ImageCandidate[]` (same interface as 05-01, reuse the type from ipc-types.ts):
   ```typescript
   interface ImageCandidate {
     id: string;           // "met_grain_12345" or "wiki_wine_67890"
     goodId: string;       // "grain" etc.
     sourceUrl: string;    // clickable museum page URL (for user to verify)
     imageUrl: string;     // direct image URL (for preview display)
     title: string;
     attribution: string;
     source: "met" | "wikimedia";
   }
   ```
   Note: ImageCandidate already has both portId and goodId fields optional — if you added portId in 05-01, just add optional goodId field alongside it.
6. Add sequential 1-second delays between Met detail API calls.
7. Register handler in ipc/game.ts. The ImageCandidate type should already exist from 05-01 — do not redefine it, just add the optional goodId field if missing.

Do NOT implement download logic here. This handler only searches and returns candidates.

Error handling: if both Met searches fail, log the error and proceed to Wikimedia. If both sources fail, return empty array.
